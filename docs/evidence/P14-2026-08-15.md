## Governing model and independent reference results

The normalized state uses fixed scales of `1 m` for position and `1 m/s` for rate:

```text
d(position)/dt = rate
d(rate)/dt     = -0.5 * rate
A = [0 1; 0 -0.5]
C_position = [sensor_gain 0]
O_continuous = [C; C*A]
```

`model.m` forms the exact free-response `Ad`, constructs the physical-state observation matrix
`O=[C;C*Ad;...;C*Ad^N]`, explicitly scales its columns by the declared state scales, computes the
2×2 scaled Gramian, and reconstructs a unique full-rank initial state with explicit scalar 2×2
arithmetic. It does not call `obsv`, `rank`, `gram`, `c2d`, `ss`, `lsim`, `pinv`, `expm`, or an ODE
solver.

Independent Python arithmetic retained these baseline facts for position-sensor gain
`1 sensor unit/m`, damping `0.5 1/s`, window `2 s`, sample interval `0.05 s`, initial state
`[0.8 m; 0.6 m/s]`, and comparison state `[1.8 m; 0.6 m/s]`:

- finite-window observability rank: `2`;
- observation Gramian entries: approximately `41`, `30.05984204431758`, and
  `27.697626563001304`;
- scaled minimum singular value: approximately `1.8873067184396513 sensor unit`;
- scaled condition number: approximately `4.276289080641569`;
- worst-case inverse noise gain: approximately `0.529855582152942 scaled state/sensor unit`;
- candidate-output RMS separation: `1 sensor unit`;
- reconstructed initial-state error: less than `2e-14` in normalized state coordinates.

For the sensor-gain sweep `[0.25, 0.5, 1, 1.5, 2]`, every case remains rank two, the scaled minimum
singular value and candidate-output separation are proportional to gain, and worst-case inverse noise
gain is inversely proportional to gain. For observation windows `[0.1, 0.25, 0.5, 1, 2, 4] s`, the
scaled minimum singular value increases monotonically while inverse noise gain decreases, with sensor,
dynamics, sample interval, and initial states fixed.

With rate-only measurement, rank is one: the sensor still produces a decaying rate output, but two
states separated by a constant `1 m` position offset have exactly identical measurement histories.
The model marks the full initial state non-unique and exposes its estimate as N/A/`NaN` rather than
inventing a zero position. With zero sensor gain, rank is zero and all outputs are zero. A fresh call
with position measurement restored recovers rank two, candidate separation, and reconstruction. The
largest accepted independent reference grid contains 5,001 samples over 5 seconds and remains finite.
These are independent Python reference-simulation results, not MATLAB-runtime numerical evidence.

## Figure, control, metric, and unit inventory

### Scripted figures

`experiment.m` defines five deterministic figures with ten labeled axes:

1. baseline candidate position and shared rate trajectories;
2. baseline candidate measurement histories and the two scaled observation-column effects;
3. position-sensor sensitivity sweep for weakest singular value, output separation, and inverse gain;
4. observation-window sweep for weakest singular value, inverse gain, and condition number;
5. rate-only broken outputs and restored position-measurement outputs.

### Interactive view and controls

`interactive.m` defines one `uifigure` with two axes: candidate normalized state histories and
candidate sensor-output histories. It exposes:

- sensor-sensitivity slider: `0.25–2 normalized output/state`, baseline `1`;
- observation-window spinner: `0.1–5 s`, step `0.1 s`, baseline `2 s`, aligned to the `0.05 s`
  sample grid;
- position versus rate-only broken measurement dropdown;
- reset button restoring sensitivity `1`, window `2 s`, and position measurement;
- value-changing/value-changed callbacks with rank, scaled singular value, output separation,
  inverse noise gain, and uniqueness feedback.

### Metrics and units

- continuous observability determinant: used only for zero/nonzero structure;
- finite-window observability rank: visible state directions, `0–2`;
- minimum singular value and condition number: coordinate-scaled diagnostics under the declared
  `1 m` and `1 m/s` state scales;
- worst-case inverse noise gain: scaled state per sensor unit;
- position and rate: metres and metres per second;
- sensor output and candidate separation: sensor units;
- position-sensor gain: sensor unit per metre;
- rate-sensor gain in the broken case: sensor unit per metre per second;
- time, observation window, and sample interval: seconds;
- damping: `1/s`.

## Test and failure-mode coverage

- Positive: artifact set, identity, CLI check route, deterministic repeat, exact state transition,
  observation rows, Gramian identity, recurrence, initial-state reconstruction, labels, metrics,
  controls, and tutor flow.
- Negative/broken: rate-only measurement produces a healthy signal while hiding a constant position
  offset and reducing rank to one; zero sensor sensitivity gives rank zero.
- Malformed input: nonfinite, complex, nonscalar, malformed selector, negative, too-small nonzero,
  excessive, zero-interval, under/over-window, coarse interval, misaligned grid, and initial-state
  range inputs are retained in executable MATLAB checks and static regression coverage.
- Timeout: synchronous CLI subprocess checks have a 10-second timeout.
- Cancellation: not applicable to pure bounded in-process arithmetic with no background work,
  external I/O, or persisted intermediate model state.
- Rollback/recovery: a fresh position-measurement call is compared with the isolated rate-only broken
  call; repository rollback is documented below.
- Isolation: permanent P14 tests assert P14 identity and P13 prerequisite only. They do not require
  P14 to remain latest or later modules to remain scaffolded. Shared tests derive the moving
  contiguous frontier from canonical manifest state. One behavioral test runs `start P14` and
  `continue` in a temporary repository. A separate behavioral regression seeds current-module,
  completion, and note state, runs `check P14`, and requires that progress file to remain byte-for-byte
  unchanged. Neither test can mutate real learner progress.
- Compatibility: deterministic base MATLAB arithmetic only, with explicit transparent operations and
  no Control System Toolbox dependency.
- Resource bounds: at most 5,000 propagation steps/5,001 samples. Oversized grids are rejected before
  observation allocation; the largest accepted grid is independently simulated for finite state and
  output histories.

## Independent system-risk review

The independent review found one low-severity behavioral coverage gap. The focused check-route test
proved the P14 public command and expected output but did not seed or compare learner progress, even
though its name and this evidence described the route as non-mutating. A future check-route regression
could therefore overwrite a learner's current module, completion record, or note while the focused
suite continued to pass.

`tests/test_p14_module.py` now adds an isolated temporary-repository regression that seeds all three
state classes, runs `learn check P14`, verifies the expected route with no stderr, and requires the
progress file to remain byte-for-byte unchanged. The original output-routing assertion remains
separate. No product code, model invariant, deterministic gate, managed contract, or validation claim
boundary was weakened or broadened.

The review also covered sampled observability arithmetic, reconstruction, rate-only failure and
recovery, UI callback lifetime, resource rejection before allocation, public routing, rollback,
allowed-path scope, external-I/O and dependency absence, claim language, and EOF formatting. It found
no additional material correctness, concurrency, lifetime, resource, migration, compatibility,
security, licensing, or recovery defect inside the active-batch repair boundary. MATLAB-runtime,
remote-CI, and manual instructional-playtest gaps remain as documented below.
