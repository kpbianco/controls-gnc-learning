## Governing model and independent reference results

The normalized state uses fixed scales of `1 m` for position and `1 m/s` for rate:

```text
d(position)/dt = coupling * rate
d(rate)/dt     = -0.5 * rate + input_gain * command
A = [0 coupling; 0 -0.5]
B = [0; input_gain]
C = [B A*B]
det(C) = -coupling * input_gain^2
```

`model.m` forms the exact zero-order-held `Ad` and `Bd`, constructs the physical-state matrix
`R=[Ad^(N-1)Bd,...,Bd]`, explicitly scales its rows by the declared state scales, computes the 2×2
scaled Gramian, and solves the full-rank rest-to-rest position target with explicit scalar 2×2
arithmetic. It does not call `ctrb`, `rank`, `gram`,
`c2d`, `ss`, `lsim`, `pinv`, `expm`, or an ODE solver.

Independent Python arithmetic retained these baseline facts for input gain `1 (m/s^2)/command`,
coupling `1`, damping `0.5 1/s`, horizon `2 s`, held interval `0.05 s`, and target
`[1 m; 0 m/s]`:

- finite-horizon controllability rank: `2`;
- scaled minimum singular value: approximately `0.1162100350701485`;
- command-energy proxy: approximately `1.6508722484834308 command^2*s`;
- peak command magnitude: approximately `1.5033135650687792 command`;
- terminal residual norm: less than `2e-14` in normalized state coordinates;
- Gramian entries: approximately `0.06722748992859534`, `0.03996214326999061`, and
  `0.043230984247860524`.

For the input-gain sweep `[0.25, 0.5, 1, 1.5, 2]`, every case remains rank two, the scaled
minimum singular value is proportional to gain, peak command is inversely proportional to gain,
and command energy is inversely proportional to gain squared. For maneuver times
`[0.5, 1, 2, 3, 4] s`, the scaled minimum singular value increases while energy and peak command
decrease monotonically with all other model parameters fixed.

With coupling disconnected, rank is one: the fixed probe produces exactly the same rate history as
the intact case but position stays exactly zero, and the position target retains a `1 m` residual.
The model marks that equality-constrained target infeasible, exposes no minimum-energy command, and
reports effort as N/A/`Inf` rather than mislabeling its zero failed-transfer attempt as an optimum.
With input gain zero, rank is zero and both probe states remain zero. A fresh call with coupling
restored to one recovers rank two and reconstructs the target. These are independent Python
reference-simulation results, not MATLAB-runtime numerical evidence.

## Figure, control, metric, and unit inventory

### Scripted figures

`experiment.m` defines five deterministic figures with ten labeled axes:

1. baseline position transfer and rate return;
2. baseline held command and fixed-probe state effects;
3. actuator-effectiveness sweep scaled singular value and command energy;
4. maneuver-time sweep scaled singular value, energy, and peak command;
5. disconnected-coupling versus restored position and rate probe response.

### Interactive view and controls

`interactive.m` defines one `uifigure` with two axes: rest-to-rest target transfer and fixed-probe
state effects. It exposes:

- input-gain slider: `0.25–2 (m/s^2)/command`, baseline `1`;
- maneuver-time spinner: `0.5–5 s`, step `0.25 s`, baseline `2 s`, aligned to the `0.05 s`
  held-command grid;
- intact/disconnected coupling dropdown;
- reset button restoring gain `1`, horizon `2 s`, and intact coupling;
- value-changing/value-changed callbacks with rank, scaled singular value, energy, peak command,
  residual, and interpretation feedback.

### Metrics and units

- continuous controllability determinant: used only for zero/nonzero structure, not as a universal
  strength score;
- finite-horizon controllability rank: state directions, `0–2`;
- minimum singular value and condition number: coordinate-scaled numerical diagnostics under the
  declared `1 m` and `1 m/s` state scales;
- terminal position/rate and residual: metres, metres per second, and normalized state coordinates;
- command energy: `command^2*s`;
- peak command: command units;
- time and held interval: seconds;
- input gain: `(m/s^2)/command`;
- damping: `1/s`; coupling: dimensionless.

## Test and failure-mode coverage

- Positive: artifact set, identity, CLI check route, deterministic repeat, exact ZOH matrices,
  reachability chronology, Gramian identity, recurrence, target reconstruction, labels, metrics,
  controls, and tutor flow.
- Negative/broken: disconnected coupling preserves rate response while freezing position and
  reducing rank; zero actuator effectiveness gives rank zero.
- Malformed input: nonfinite, complex, nonscalar, negative, too-small nonzero, excessive,
  zero-interval, under/over-horizon, coarse interval, misaligned grid, and target-range inputs.
- Timeout: synchronous CLI subprocess checks have a 10-second timeout.
- Cancellation: not applicable to pure bounded in-process arithmetic with no background work,
  external I/O, or persisted intermediate model state.
- Rollback/recovery: a fresh intact-coupling call is compared with the isolated broken call; the
  repository rollback is documented below.
- Isolation: permanent P13 tests assert P13 identity and P12 prerequisite only. They do not require
  P13 to remain the latest module or require later modules to remain scaffolded. Shared tests derive
  the moving contiguous frontier from canonical manifest state. The focused P13 behavioral test
  runs `start P13` and `continue` in a temporary repository, verifies persisted P13 selection and
  identical launch output, and cannot mutate real learner progress. The P13 check-route test also
  remains non-mutating.
- Compatibility: base MATLAB arithmetic only, with explicit transparent fallbacks and no Control
  System Toolbox dependency.
- Resource bounds: at most 5,000 held-command steps and 100 command magnitude in the retained view;
  oversized grids are rejected before reachability allocation. The maximum accepted grid is checked
  for finite state and target reconstruction.

proved the public `check` route but did not behaviorally retain the learner-facing
