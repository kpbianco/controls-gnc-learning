## Governing model, event order, and bounded inputs

The controller uses the newest delivered position and velocity measurement:

```text
u_request = clip(18*(r-x_measured) - 8*v_measured, -30, +30) N
x_dot = v
m*v_dot = u_applied - 1.2*v
```

For a held applied force over plant tick `dt`, with `a=exp(-1.2*dt/m)`, the transparent exact transition is

```text
v_next = a*v + (1-a)*u/1.2
x_next = x + (m/1.2)*(1-a)*v + (dt/1.2-m*(1-a)/1.2^2)*u
```

At each integer plant tick the source evaluates cancellation first. Cancellation purges queued work before
a same-tick delivery. Otherwise the source enqueues the current plant measurement on a controller release,
delivers a due measurement, computes from the newest delivered timestamp, deterministically sends or drops
the command, delivers a due command, separates startup-safe from stale-command timeout, selects held force
or safe zero, and propagates the plant. Zero latency therefore has no hidden tick.

Accepted inputs are controller period `0.02–0.2 s`, one-way latency `0–0.2 s`, watchdog timeout `0.05–1 s`,
integer drop cadence `0–20` where zero disables dropping, cancellation within the virtual run or positive
infinity, mass `0.5–5 kg`, plant tick `0.005–0.02 s`, and duration `4–20 s`. Period, latency, timeout,
cancellation, duration, and the midpoint reference reversal must align with the plant grid. All derived
grid checks and the `201–4,001` sample cap run before histories are allocated. Propagated position and
velocity are bounded to `10 m` and `30 m/s`; a deterministic `P24:ResponseBound` stops a view that exceeds
them.

The baseline reference is `+1 m` until `4 s`, then `-0.5 m`. It uses controller period `0.05 s`, one-way
latency `0.01 s`, timeout `0.2 s`, no loss or cancellation, mass `1.5 kg`, tick `0.01 s`, and duration `8 s`.
