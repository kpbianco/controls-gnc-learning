## Model and numerical contract

The fixed plant and controller constants are `Kp=2 actuator/output`,
`Ki=1 actuator/(output*s)`, plant time constant `1 s`, static gain
`1 output/actuator`, and symmetric applied-control limit `±1 actuator`. The integral state is the
integral control contribution in actuator units. The two paths use:

```text
uRequested = Kp*error + integralState
uApplied = clamp(uRequested, -1, +1)
unprotected: integralStateDot = Ki*error
protected:   integralStateDot = Ki*error + polarity*Kaw*(uApplied-uRequested)
```

`Kaw` therefore has units `1/s`. Correct polarity is `+1`; `-1` is deliberately broken. The
reference is infeasible `+2 output` before the exact demand-switch event and feasible `-0.5 output`
at and after it. The plant uses the exact held-input first-order transition on every actual interval;
the integral state uses the same event-aligned interval duration.

Independent Python reference arithmetic retained these baseline facts for `Kaw=1 1/s`, demand
duration `3 s`, horizon `12 s`, and nominal interval `0.01 s`:

- unprotected integral state at reversal: approximately `3.9549719147 actuator`;
- protected integral state at reversal: approximately `-0.1497327231 actuator`;
- unprotected applied-command reversal delay: approximately `2.02 s`;
- protected applied-command reversal delay: `0 s`;
- protected and unprotected output/applied control remain identical while both paths share the
  positive clamp;
- the protected post-release integral absolute error is less than one quarter of the unprotected
  value;
- `Kaw=0` makes both paths and both correction polarities exactly identical;
- wrong polarity at `Kaw=0.5 1/s` grows hidden integral state beyond `100 actuator` by `8 s` while
  the plant remains bounded by the actuator clamp; restoring polarity bounds the state and recovers.

These are reference-simulation results from Python, not MATLAB-runtime numerical evidence.

`interactive.m` defines one `uifigure` with two axes: output comparison and integral-state/applied-

references use step rendering so neither the metric window nor visual interpolation distorts the
event comparison.

### Controls

- anti-windup gain slider: `0–8 1/s`, baseline `1 1/s`;
- high-demand duration slider: `1–5 s`, baseline `3 s`;
- reset button restoring both baseline values;
- value-changing and value-changed callbacks for immediate feedback.

### Metrics

- integral state at the demand reversal (`actuator`);
- applied-command reversal delay (`s`);
- settling time within `0.02 output` (`s`, or `NaN` when not settled in view);
- post-release integral absolute error (`output*s`);
- maximum absolute integral state (`actuator`);
- maximum requested-applied command gap (`actuator`);
- final tracking error (`output`);
- saturation state (logical).

### Units

Time and duration are seconds; plant reference/output/error are output units; requested/applied
control, command gap, and integral state are actuator units; gain `Kaw` is `1/s`; post-release error
area is `output*s`.

## Independent system-risk review and repairs

The final bounded review found and repaired these in-scope issues:

1. The interactive duration slider passed a fixed `12 s` horizon. Moving demand duration from
   `1 s` to `5 s` therefore shortened the post-release metric window from `11 s` to `7 s`, so the
   nominal one-lever experiment also changed how long recovery error was accumulated. The callback
   now sets the horizon to `demandDurationSec+9`, matching the scripted sweep. The new
   `test_duration_lever_preserves_recovery_window_behaviorally` independently retains exactly nine
   recovery seconds and 901 post-release samples for representative slider values; `run_checks.m`
   also pins the nine-second window, fixed gain, fixed limit, and fixed time step.
2. Reference histories were drawn with line interpolation across the exact demand switch even
   though the model defines a held step. Experiment and interactive reference traces now use
   `stairs`, and focused source regressions retain those presentation calls.
3. The feasibility assertion compared output units directly with actuator units. It now converts
   actuator authority through the declared plant static gain before classifying the high and
   recovery references.
4. Learner-facing claim text described retained validation as static only despite the separately
   classified independent Python simulation. It now states `static plus independent Python
   reference simulation` while continuing to exclude MATLAB-runtime and MATLAB numerical-fidelity
   evidence.
5. The retained Markdown lacked the structured evidence record used by the repository evidence
   schema. A P12 record now maps commands, acceptance, changed invariants, residual risks, and
   unperformed validation, and it validates against
   `.github/codex/schemas/evidence.schema.json`.
